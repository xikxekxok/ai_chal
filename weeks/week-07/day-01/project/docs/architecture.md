# Архитектура TaskBoard

## Слои

1. **API** — FastAPI-роуты: healthcheck и CRUD задач.
2. **Models** — Pydantic-схемы запроса/ответа (`Task`, `TaskCreate`).
3. **Store** — словарь в памяти процесса; данные теряются при рестарте.

Нет БД, очередей и аутентификации — учебный контур.

## Потоки

### Создание задачи

```
клиент → POST /tasks → валидация TaskCreate → store.create → 201 + Task
```

Новый `id` — UUID4. Начальный `status` всегда `todo`. Поле `created_at` — ISO-8601 UTC.

### Список задач

```
клиент → GET /tasks → store.list → 200 + массив Task
```

Фильтров и пагинации нет: возвращаются все задачи в порядке создания.

### Health

```
клиент → GET /health → {"status": "ok"}
```

Используется для smoke-проверок без обращения к store.

## Ограничения

- Один процесс = одно хранилище.
- Нет `PATCH`/`DELETE` в текущей версии API (см. `api.yaml`).
- Максимальная длина `title` — 200 символов.
