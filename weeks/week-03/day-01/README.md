# Неделя 3, день 1 — модель памяти «Хvостik»

## Задание

Три слоя памяти ассистента приюта:

| Слой | Назначение | Файлы |
|------|------------|-------|
| **short** | текущий диалог | `data/short/dialog.json` |
| **working** | факты по каждому опossumу | `data/working/<name>.json` |
| **long** | устав приюта | `data/long/charter.md` |

После каждого хода LLM-классификатор решает, сохранять ли факты в **working** или **long** (или только в short).

## Запуск

```bash
source .venv/bin/activate
python weeks/week-03/day-01/main.py --demo
```

Один прогон `--demo` — три диалога:

1. **Приём Пушка** — факты попадают в working.
2. **Следующий день** — user_sim помнит прошлую смену через **саммари**, не полный transcript; ассистент опирается на working и long.
3. **Директор** — новые часы 18:00–08:00 в long.

В начале demo — блок «что происходит» (агент, слои памяти, текущее состояние).
Между диалогами short очищается; working и long накапливаются; после каждой сессии LLM пишет саммари для user_sim.

Дополнительно:

```bash
python weeks/week-03/day-01/main.py --chat
python weeks/week-03/day-01/main.py --show-memory
python weeks/week-03/day-01/main.py --clear short|working|all|all-long-reset
```

## На видео

- `[demo] что происходит` — агент, слои, начальное состояние памяти
- `[demo] dialog 1/2/3` — границы сессий
- `[summary]` — саммари прошлой смены для user_sim
- `[user]` / `[agent]` — полные реплики
- `[memory] classifier → …` — куда сохранено
- `[retry]` — повтор запроса при таймауте/сети (до 4 попыток, timeout 45с)
- финальный dump слоёв и чеклист ✓/✗
