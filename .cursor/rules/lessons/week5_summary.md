## Главная тема недели

Пятая неделя посвящена **RAG (Retrieval Augmented Generation)** — паттерну дополнения ответов LLM **внутренними знаниями** прямо во время инференса.

Модель получает контекст не только из обучающей базы, но и из **специфических документов системы**: вики, Confluence, внутренняя документация, корпоративные политики.

RAG происходит **во время инференса** — это не вызов внешнего инструмента в смысле MCP, а **подгрузка найденных фрагментов в prompt** модели.

## Проблемы без RAG

1. **Неполный контекст** — модель обучена на общих интернет-данных, не на внутренних процессах организации.
2. **Смешанные данные** — в базе знаний несколько версий процессов, устаревшие и актуальные документы; модель не разграничивает их как человек.
3. **Галлюцинации** — «среднее по больнице» вместо конкретной политики команды.
4. **Ложно-положительные ответы** — ответ звучит правдоподобно, но не соответствует вашим документам; самый опасный сценарий.

## Способы улучшения LLM

| Подход | Что делает | Примеры |
|--------|------------|---------|
| **Промпт-оптимизация** | указание через контекст | MD-файлы, skills, субагенты |
| **RAG** | контекст из внешних знаний | векторные БД, эмбеддинги |
| **Fine-tuning** | изменение весов модели | обучение на специализированных данных |

Три метода **аддитивны**, не взаимоисключающие. Современные системы часто комбинируют все три.

## RAG и MCP

| | MCP | RAG |
|---|-----|-----|
| Источник | внешние API, tools, сторонние сервисы | **внутренние** документы организации |
| Механизм | tool call → handler → API/CLI | retrieve → чанки в **prompt** |
| Когда | актуальное состояние систем, действия | семантический поиск по базе знаний |

MCP и RAG решают разные задачи; на практике агент может использовать оба.

## Пайплайн RAG

**Без RAG:** запрос → модель → ответ из общей тренировочной базы (возможна галлюцинация).

**С RAG:**

1. Пользователь задаёт вопрос.
2. Запрос (или его переформулировка) идёт в **векторную базу** документов.
3. Находятся семантически похожие **чанки** текста.
4. Чанки **комбинируются с промптом**.
5. Модель возвращает ответ **со ссылкой на источник**.

Пример хорошего ответа:

> «Согласно политике code review ([ссылка на Confluence]), требуется минимум 2 аппрува до мержа, максимальное время ревью — 24 часа.»

## Эмбеддинг-модели vs генеративные

| Тип | Вход | Выход | Назначение |
|-----|------|-------|------------|
| **Генеративные** (ChatGPT, Claude, DeepSeek) | текст | текст | ответы, понимание контекста |
| **Эмбеддинг-модели** (Ollama, nomic-embed-text) | текст | вектор (числа) | семантический поиск |

На неделе: **генерация** — через Dockhost (как недели 1–4); **эмбеддинги** — через **Ollama** локально (или замена на облачный embedder по заданию).

## Эмбеддинги

**Вектор** — массив чисел, представляющий текст (768, 1024 и более измерений).

### Косинусное сходство

- `1` — тексты близки по смыслу;
- `0` — разные темы;
- `-1` — противоположные по смыслу.

Близкие по смыслу тексты — близки в векторном пространстве; чем больше размерность, тем меньше «коллизий».

### Pipeline эмбеддинга

1. **Токенизация**
2. **Embedding layer**
3. **Self-attention**
4. **Pooling** — один вектор на фрагмент
5. **Сравнение** с векторами в базе

## Чанкинг

Перед векторизацией текст нарезается на **чанки**.

| Метод | Плюсы | Минусы |
|-------|-------|--------|
| **Фиксированный размер** (каждые N токенов) | просто | разрез посередине предложения |
| **Семантический** (абзацы, разделы) | точнее | сложнее реализовать |

**Overlap (перекрытие)** снижает потерю контекста на границах:

```
Без overlap: [1-500] [501-1000] [1001-1500]
С overlap:   [1-500] [451-950]  [901-1400]
```

Ориентир: **500–1000 токенов** на чанк; размер и overlap — **экспериментально** под данные.

## Ollama для эмбеддингов

Рекомендуемый инструмент для локальных эмбеддингов:

- **Приватность** — данные не покидают машину;
- **Стоимость** — нулевая (кроме железа);
- **Размер моделей** — небольшие (миллионы параметров, не миллиарды);
- **Совместимость** — можно заменить на облачный embedder.

Установка:

```bash
# macOS: brew install ollama
ollama pull nomic-embed-text
```

HTTP (локально):

```
POST http://localhost:11434/api/embeddings
```

На VPS — заменить `localhost` на адрес сервера.

## Реранкинг

**Проблема:** топ-k по эмбеддингам может включать тематически похожие, но **нерелевантные** чанки.

**Реранкинг** — CrossEncoder переоценивает пары (запрос, чанк):

1. Быстрый retrieve топ-20;
2. Медленный rerank → топ-N для LLM;
3. Модель получает более точный контекст.

Замедляет пайплайн, но повышает точность.

## Метрики качества RAG

1. **Качество ретривела** — доля релевантных чанков в выдаче.
2. **Правдивость (groundedness)** — ответ опирается на чанки, есть ссылки на источники.
3. **Точность финального ответа** — сравнение с эталонами; регрессионные Q&A.

Минимальная проверка:

- [ ] Правильные чанки найдены?
- [ ] Ответ основан на контексте (есть ссылки)?
- [ ] Финальный ответ правильный?

## Когда RAG не поможет

| Проблема | Альтернатива |
|----------|--------------|
| Мало или плохие данные | fine-tuning |
| Сложная логика («если X, то Y») | промпт-инжиниринг, агенты |
| Нужен стиль общения | агенты, инструменты |
| Нечитаемые форматы | multimodal RAG, OCR |

RAG хранит **сырые векторизованные фрагменты** для поиска — не меняет поведение модели.

## Где применять RAG

- корпоративные базы знаний (Confluence, вики, чаты);
- privacy-сценарии (локальный контур);
- специализированные домены (медицина, инженерия);
- аналитика трендов по векторизованным данным;
- «цифровой двойник» — переписки, звонки в персональную базу.

## Цели недели

2. реализовать **поиск** по базе знаний;
3. интегрировать **RAG** в агента;

## Практический вывод

RAG дополняет LLM **внутренними знаниями во время ответа**, не заменяя промпт-инжиниринг, fine-tuning или MCP.

Хороший RAG-пайплайн: осмысленный **чанкинг с overlap**, качественные **эмбеддинги**, измеримый **retrieve**, опциональный **rerank**, **цитирование источников** в финальном ответе.

К концу недели нужно уметь собрать end-to-end цепочку и **оценивать качество** — не только «ответ звучит правдоподобно».
