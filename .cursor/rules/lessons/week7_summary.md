## Главная идея

Заключительная практическая неделя: собрать знания курса в **работающую систему**. Фокус — агенты как мини-ОС, делегирование субагентам, system tools / MCP, надёжные AI-пайплайны с мониторингом и обработкой ошибок. Цель — **реальный прототип или продукт**, а не демонстрация технологии.

---

## LLM Agent как мини-ОС

Современный AI-агент управляет инструментами и ресурсами подобно ОС: файлы, bash, MCP, RAG. Примеры среды: Cursor, Claude Code, OpenCode.

Задача продукта: пользователь решает задачу **за минимум итераций** — в идеале один раз сказал «что делать», и система довела до результата без потери контекста.

---

## Субагенты и паттерны

**Субагент** — специализированный агент на одну подзадачу. Имеет **собственное** контекстное окно → оркестратор не раздувает свой контекст.

| Паттерн | Смысл | Когда |
|---------|-------|--------|
| **Fan-out** | оркестратор запускает несколько субагентов **параллельно** | независимые подзадачи (бэкенд + мобилка) |
| **Chain** | результат одного → вход следующего | последовательные этапы |
| **Router** | выбор субагента по условию / типу запроса | разные типы задач в одном входе |

Параллель (Fan-out) часто ускоряет цепочку в разы vs длинный sequential chain.

---

## System tools

Инструменты окружения: чтение/запись файлов, bash, запуск приложений, MCP, RAG.

**Tool Registry + Tool Executor:** все tools в реестре; executor по запросу LLM находит, запускает, возвращает результат.

---

## Dangerous operations

Опасные операции (удаление файлов, `git push` и т.п.) — **обязательное** подтверждение пользователя (Human-in-the-Loop). Идеально: отдельный анализ «опасно ли» + вопрос юзеру.

Не должно быть полностью автоматического сервиса без возможности вмешательства человека.

---

## AI Pipeline

Автоматизированная цепочка:

```
триггер (PR / schedule / событие) → AI-агент → действие / результат
```

Классический пример: авто-ревью кода при Pull Request.

---

## Error handling

| Стратегия | Смысл |
|-----------|--------|
| **Retry** | повтор с другим промптом / моделью |
| **Fallback** | альтернативная стратегия или эскалация человеку |
| **Timeouts** | ограничение времени шага / пайплайна |

Критические сбои → уведомление человека, не «тихий» fail.

---

## Метрики

| Метрика | Что меряем |
|---------|------------|
| **Latency** | P50 / P95 / P99 времени выполнения |
| **Cost** | токены / стоимость на операцию (напр. на PR) |
| **Quality** | оценка человеком (шкала 1–10) |
| **Success rate** | доля прогонов без вмешательства человека |

Практика: baseline → тест на исторических эталонах → сравнение версий промптов/моделей.

3. Tool Registry + Executor; HITL на опасные операции.
4. Простой AI-пайплайн (напр. ревью PR).
5. Retry / Fallback / человек в контуре.

7. **Реальный продукт / прототип** — не только учебное демо.

## Практический вывод

Неделя про **сборку**: оркестрация, tools, пайплайны, надёжность. Минимализм в коде курса: показать нужный паттерн дня, не строить «полную ОС». Параллель субагентов экономит время; HITL обязателен на опасном и в production-цепи.

## Цитаты

- «LLM Agent это, по сути, мини-OS в современном мире.»
- «Задача пользователя — за минимальное количество итераций… в идеале один раз сказал, что делать.»
- «Цепи в chain — 16–20 минут; параллель субагентов — в 2–10 раз быстрее.»
- «Опасные операции… спрашивать у юзера.»
- «Всегда предусмотреть human в этой цепи — не полностью автоматический сервис.»
- «На этой неделе… берите реальные продукты, пробуйте, ошибайтесь.»
