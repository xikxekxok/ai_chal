# Week 07 Day 03

- Собрал самодостаточный CLI-сервис саппорта в `weeks/week-07/day-03/`: локальный RAG по markdown KB, агентский tool-loop и Dockhost `llm.py`.
- Добавил локальный MCP CRM по `data/crm.json` со stdio-сервером и read-only tools: `list_tickets`, `get_ticket`, `get_user`.
- Подготовил demo-сценарий под видео: `--show-kb`, `--mcp-test`, `--ask`, `--demo`, плюс README с командами запуска.

## Интересное

- Для задания хватило простого keyword-based retrieval без embeddings: меньше зависимостей и быстрее smoke-проверка.
- Ticket/user контекст подмешивается до ответа агента, а KB и CRM tools остаются доступны модели в том же цикле.

## Проблемы и решения

- Нужно было не задеть незакоммиченные изменения в основном дереве, поэтому работал в отдельном git worktree на новой ветке.
- Интеграция с LLM зависит от `DOCKHOST_AI_KEY` и сети, поэтому без API отдельно предусмотрены полноценные smoke-команды.
- На видео было неясно, какой вопрос отвечает ассистент: вопрос уходил в LLM, но в stdout не печатался. Исправил: перед tools/ответом полный `[user]` (и ticket id).

## Вывод

- Для видео удобно показывать `--demo`, а для локальной отладки хватит `--show-kb` и `--mcp-test`.
- В stdout перед tools/ответом явно печатается полный `[user]` вопрос (с ticket id), без усечения — так на видео видно, на что отвечает ассистент.
